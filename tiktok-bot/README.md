# Бот TikTok

Отдельный от Pulse сервис. Пост Telegram-канала, который вы переслали боту, превращается в вертикальный ролик
1080×1920 и уходит во «Входящие» TikTok. Остальные посты канала бот не трогает: что пойдёт в TikTok, решаете вы. Владелец открывает уведомление в приложении TikTok, добавляет звук, вставляет подпись и публикует.
Копия ролика и готовая подпись приходят владельцу в личку бота. После публикации бот следит за просмотрами и лайками
ролика и отдаёт их таблицей — это данные для анализа, какие посты заходят в TikTok.

Ролик — скриншот поста таким, каким его видят в Telegram: бот открывает страницу встраивания
`t.me/<канал>/<номер>?embed=1` в безголовом Chromium, прячет счётчик просмотров и пишет дату по-русски.

- **Пост с видео** — видео играет в рамке плеера на скриншоте, целиком (до `TIKTOK_BOT_MAX_VIDEO_SECONDS`) и со своим
  звуком: выглядит как запись экрана Telegram. Файл берётся из CDN Telegram по ссылке со страницы поста, поэтому
  лимит Bot API в 20 МБ на него не действует. Если пропорции видео и рамки различаются, поля заполняет размытый кадр.
- **Пост с GIF** — GIF крутится, пока читается пост.
- **Пост без видео** — скриншот стоит на экране время чтения (8–45 секунд); высокий пост плавно прокручивается.

Карточка поста держится в безопасной зоне кадра: снизу и справа её закрывали бы подпись и кнопки TikTok. Если страницы
поста нет (приватный канал, пост удалён), ролик собирается по-старому — слайдами из заголовка, картинок и текста.
Языковая модель не нужна: пост уже написан.

## Почему «Входящие», а не сразу в профиль

TikTok Content Posting API публикует напрямую (Direct Post) только у приложений, прошедших аудит. До аудита все такие
посты видны только автору, а аккаунт должен быть приватным. Загрузка во «Входящие» (Upload) работает сразу: публикацию
подтверждаете вы, одним нажатием в приложении. Фото-посты API принимает только по ссылке с подтверждённого домена,
поэтому бот собирает видео.

## Настройка

### 1. Бот в Telegram

1. Создайте у [@BotFather](https://t.me/BotFather) **нового** бота (не тот, через которого публикует Pulse:
   один токен нельзя одновременно читать двумя программами).
2. Добавлять бота в канал не нужно: он работает только с постами, которые вы ему пересылаете.
3. Напишите боту любое сообщение — он ответит вашим числовым id для `TIKTOK_BOT_OWNER_ID`.

### 2. Приложение TikTok

1. Войдите в [TikTok for Developers](https://developers.tiktok.com/) и создайте приложение (Manage apps → Connect an app).
2. Добавьте продукты **Login Kit** и **Content Posting API**. В Content Posting API включать Direct Post не нужно.
3. В Login Kit укажите Redirect URI — любой https-адрес, например страницу своего сайта или `https://example.com/tiktok/callback`.
   Страница может не существовать: боту нужен только код, который TikTok допишет к этому адресу.
4. Скоупы: `user.info.basic`, `video.upload` и `video.list`. Последний даёт продукт **Display API** — добавьте его тоже:
   без него бот загружает ролики, но не видит их статистику.
5. Пока приложение не прошло ревью TikTok, войти в него могут только аккаунты, добавленные в Sandbox
   (Sandbox → Target users): добавьте туда свой аккаунт TikTok.

### 3. Переменные окружения

В `.env` в корне репозитория (образец — в `.env.example`, блок «бот TikTok»):

| Переменная | Что указать |
|---|---|
| `TIKTOK_BOT_TELEGRAM_TOKEN` | токен нового бота |
| `TIKTOK_BOT_OWNER_ID` | ваш id в Telegram |
| `TIKTOK_BOT_CHANNEL` | необязательно: `@имя_канала` для подписи, если пост переслан из приватного канала без @имени |
| `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET` | ключи приложения TikTok |
| `TIKTOK_REDIRECT_URI` | тот же адрес, что в Login Kit |
| `TIKTOK_BOT_HASHTAGS` | необязательно: хештеги в конец подписи |
| `TIKTOK_BOT_CHANNEL_TITLE` | необязательно: название на финальном кадре (по умолчанию — название канала) |
| `TIKTOK_BOT_MIN_TEXT_CHARS` | короче — ролик не делается, бот об этом напишет (по умолчанию 40) |
| `TIKTOK_BOT_MAX_VIDEO_SECONDS` | видео поста в ролике не длиннее (по умолчанию 600 — предел TikTok для загрузки через API) |
| `TIKTOK_BOT_SCREENSHOT` | `0` — ролик из слайдов вместо скриншота поста |
| `TIKTOK_BOT_TIMEZONE` | часовой пояс времени поста на скриншоте (по умолчанию `Europe/Moscow`) |

### 4. Запуск и подключение TikTok

```bash
docker compose -f docker-compose.tiktok.yml up -d --build
```

Отправьте боту `/auth`, откройте ссылку, войдите в TikTok и пришлите боту адрес из строки браузера, на который вас
переадресовало (с `?code=…`). Бот обновляет доступ сам: повторный вход нужен раз в год.

## Команды

- `/auth` — подключить аккаунт TikTok;
- `/status` — подключение, последние посты и их просмотры и лайки в TikTok;
- `/export` — таблица CSV со всеми постами, роликами и их статистикой;
- переслать боту пост канала — ролик из него (из любого канала, в том числе старый пост; повторная пересылка —
  новый ролик). Альбом пересылайте целиком.

## Звук

Музыку из библиотеки TikTok через API добавить нельзя, поэтому трек выбирается в приложении при публикации из
«Входящих» («Добавить звук»): там же видны трендовые звуки. Видео поста сохраняет свой звук — бот напоминает убавить
громкость оригинала, если поверх нужен трек. Ролики без видео приходят без звука (с тихой дорожкой).

## Статистика

Каждые 15 минут бот проверяет ролики во «Входящих»: опубликованный ролик он узнаёт по статусу загрузки, а если TikTok
не вернул его id — по подписи среди последних роликов аккаунта (подпись начинается с заголовка поста). Дальше бот
снимает просмотры, лайки, комментарии и репосты, когда ролику исполняется 1 час, 6 часов, сутки, 3 дня, неделя и месяц.

`/export` присылает `tiktok_stats.csv`: строка — пересланный пост. Колонки: ссылка на пост, вид поста (`text`, `photo`,
`video`, `gif`), вид ролика (`shot` или `slides`), длина текста и ролика, время загрузки и публикации, задержка между
ними, замеры на каждой отметке (`views_24h`, `likes_24h`…) и последний замер. Номер поста совпадает с номером
сообщения канала, по нему таблица сводится с публикациями Pulse. Статистика собирается только у публичных роликов,
прошедших модерацию TikTok.

## Ограничения

- Видео, которое страница встраивания не показывает («Media is too big»), бот берёт через Bot API, а тот отдаёт
  файлы до 20 МБ: видео больше в ролик не попадёт, на скриншоте останется превью.
- Копию ролика больше 50 МБ Telegram боту отправить не даёт: такой ролик будет только во «Входящих» TikTok.
- Ролик с длинным видео собирается в несколько раз дольше самого видео: кадр 1080×1920 кодируется заново.
- Chromium с системными библиотеками увеличивает образ бота примерно на 800 МБ.
- TikTok ограничивает загрузки несколькими запросами в минуту на аккаунт и числом черновиков во «Входящих»: при
  частом постинге часть загрузок может получить отказ — бот сообщит об этом, а ролик останется у вас в личке.
