# Устранение неполадок

## Caddy не выдаёт сертификат

Проверьте `PULSE_DOMAIN`, DNS-записи `A`/`AAAA` и доступность TCP 80/443
снаружи, затем посмотрите `logs caddy`.

## Не открывается сайт

Выполните `ps`, проверьте журналы `web`, `api` и `caddy`; в production порт
`PULSE_PORT` привязан только к loopback, внешний доступ идёт через домен и Caddy.

## Порт уже занят

`port is already allocated`: порт `PULSE_PORT` занят другим стеком — укажите в
`.env` свободный и выполните `docker compose up -d`. Десктоп-приложение
подбирает порт само.

## Нет генерации или эмбеддингов

Проверьте ключ/URL/название чат-модели, наличие `bge-m3` командой
`docker compose exec ollama ollama list` и логи `api`/`worker`.

Если генерация быстро завершается с `HTTP 403 Forbidden` и сообщением
`Access denied. Please check your network settings.`, запрос отклонён сервером
или сетевым прокси, а не завершился по таймауту. Проверьте эффективные
`LLM_BASE_URL`, `LLM_MODEL` и ключ в настройках системы/окружении. Для Groq
убедитесь, что ключ и модель разрешены проекту, а исходящий адрес сервера
допускается его сетевыми ограничениями. Повторите проверку из контейнера `api`:
если 403 приходит и на запрос списка моделей, причина не в генерации Pulse;
если список моделей доступен, но запрос выбранной модели даёт 403, проверьте
доступность этой модели и ограничения проекта в панели провайдера. После смены
настроек перезапустите `api` и `worker`. Не публикуйте API-ключ в логах и
сообщениях об ошибке.

Для Telegram длинный текст отправляется вместе с картинкой через предпросмотр
ссылки над текстом: Bot API ограничивает подпись непосредственно к фото 1024
символами. Для предпросмотра используется страница источника, связанная с
выбранной обложкой: Telegram получает изображение из её `og:image`. Короткие
публикации отправляются как фото с подписью. Если загрузка обложки временно не
удалась, отправка повторится; пост не будет отмечен как успешный, если картинку
пришлось бы молча пропустить. Проверьте состояние публикации и журнал `worker`
на сообщения `image download failed`.

## «Не удалось определить адрес www.youtube.com»

Если источники YouTube падают с `Не удалось определить адрес www.youtube.com: [Errno -2] Name or service not known`,
а `youtube.com` и остальные сайты открываются, незашифрованные DNS-ответы для этого имени подменяются по дороге
(провайдер, блокировки) — даже при запросе к 1.1.1.1 или 8.8.8.8. Признак: обычный DNS отвечает «такого домена нет»,
а DNS-over-HTTPS возвращает адреса Google. Pulse тут ни при чём, но ломаются ленты каналов, субтитры, поиск видео
и подбор YouTube-каналов.

Включите надстройку с DoH-резолвером: `api`, `worker` и `searxng` будут резолвить внешние имена через
DNS-over-HTTPS (1.1.1.1 и Google), а имена сервисов стека — как раньше.

```bash
docker compose -f docker-compose.yml -f docker-compose.doh.yml up -d
```

Чтобы надстройка применялась всегда (в том числе в десктоп-приложении), добавьте в `.env`
`COMPOSE_FILE=docker-compose.yml;docker-compose.doh.yml` — в Linux и macOS разделитель `:`.
Резолвер занимает сеть `172.31.253.0/24`; если она пересекается с вашей, поменяйте подсеть и адрес
в `docker-compose.doh.yml`. На сервере, где DNS не подменяется, надстройка не нужна.

## Не хватает места

Проверьте `df -h` и содержимое `backups/`; настройки ротации ограничивают
количество и возраст бэкапов, но не заменяют контроль свободного места.

## Сброс пароля администратора

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api python -m app.admin reset-password [--email user@example.com]
```

Для локальной установки опустите `-f docker-compose.yml -f docker-compose.prod.yml`.
