# Конфигурация

## Переменные окружения

Образец со всеми значениями по умолчанию находится в [.env.example](../.env.example).
Обязательные для старта значения отмечены `:?` в Compose: `POSTGRES_PASSWORD`,
`SECRET_KEY` и `ADMIN_PASSWORD`.

| Переменная | Назначение |
|---|---|
| `POSTGRES_PASSWORD` | Пароль PostgreSQL; задайте до первого запуска и храните отдельно. |
| `SECRET_KEY` | Секрет подписи сессий, не короче 32 символов. Сгенерируйте `openssl rand -hex 32`; не меняйте после запуска. |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Учётные данные первого администратора. Пароль из `.env` применяется только при создании первого пользователя. |
| `PULSE_PORT` | Порт веб-интерфейса на хосте (по умолчанию `8080`; десктоп-приложение при занятости подбирает свободный). В production доступен только с самого сервера за Caddy. |
| `PULSE_DOMAIN` | Только для production overlay: домен Caddy, например `pulse.example.com`. |
| `COOKIE_SECURE` | `true` для HTTPS (обязательно для production), `false` для локального HTTP. |
| `LLM_PROVIDER`, `LLM_CHAT_ENABLED` | Провайдер чат-модели и включение генерации. `stub` отключает вызовы чат-модели. |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_TIMEOUT` | URL, API-ключ, имя модели и таймаут запросов к OpenAI-совместимому API. |
| `EMBED_MODEL`, `EMBED_BASE_URL`, `EMBED_API_KEY` | Модель и endpoint эмбеддингов. По умолчанию `bge-m3` загружается в Ollama из стека. |
| `OLLAMA_CONTEXT_LENGTH`, `OLLAMA_KEEP_ALIVE`, `OLLAMA_MAX_LOADED_MODELS`, `OLLAMA_NUM_PARALLEL` | Ограничения памяти и параллелизма Ollama; значения по умолчанию подходят для небольшого сервера. |
| `WORKER_CONCURRENCY` | Число фоновых worker-процессов; при локальной генерации на ограниченной памяти уменьшите до `1`. |
| `TELEGRAM_BOT_TOKEN` | Необязательный токен бота для публикации в Telegram. |
| `MINHASH_DEDUP_ENABLED` | Двухэтапная дедупликация: лексический MinHash/LSH до эмбеддингов (по умолчанию `true`). |
| `MINHASH_THRESHOLD` | Порог Jaccard по MinHash для пометки перепечатки (по умолчанию `0.82`). |
| `SEARXNG_URL` | Адрес SearXNG для источников «Веб-поиск» и поиска видео YouTube. В стеке это сервис `searxng` (`http://searxng:8080`); пусто — веб-поиск отключён. |
| `SEARXNG_SECRET` | Секрет SearXNG; по умолчанию берётся `SECRET_KEY`. |
| `YOUTUBE_PROXY_URL` | Необязательный HTTP(S)-прокси только для субтитров YouTube: с IP облачных VPS YouTube часто отвечает блокировкой. |
| `ALLOW_PRIVATE_URLS` | По умолчанию `false`: запрещает RSS-источникам и webhook обращаться к внутренним адресам. Включайте только если понимаете последствия. |
| `RETENTION_DAYS` | Срок хранения данных, для которых предусмотрена очистка (по умолчанию 30 дней). |
| `BACKUP_KEEP_DAYS`, `BACKUP_KEEP_COUNT` | Ротация локальных дампов: по умолчанию не старше 14 дней и максимум 7 файлов. |
| `BACKUP_INTERVAL_HOURS`, `BACKUP_STRIP_VECTORS` | Интервал резервного копирования (24 часа) и исключение пересчитываемых векторов из дампа (`true`). |
| `IMAGE_CACHE_MAX_MB`, `IMAGE_CACHE_MAX_AGE_DAYS` | Максимальный размер и срок хранения кэша изображений. |

После изменения `.env` примените настройки командой `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d`. Для локальной установки используйте `docker compose up -d`.

## Модели

| Компонент | Назначение |
|---|---|
| Эмбеддер (по умолчанию bge-m3 через Ollama) | группировка материалов в сюжеты и сравнение заголовков сюжета с темой проекта |
| Чат-модель (по умолчанию qwen/qwen3.8-27b через Groq) | синтез одного поста из нескольких источников, перевод |

### Режимы

- **По умолчанию** — локальный bge-m3 + облачный чат по OpenAI-совместимому API.
- **`LLM_PROVIDER=stub`** — без чат-модели: пост собирается из предложений источников, сюжеты находятся хуже.
- **Своя модель** — любой OpenAI-совместимый сервер (Ollama, vLLM, облако): `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`; для эмбеддингов отдельно `EMBED_BASE_URL`, `EMBED_API_KEY`, `EMBED_MODEL`.

Модели можно менять в интерфейсе: **Система → Состояние → Модели**. Смена эмбеддера безопасна: векторы и сюжеты пересчитываются автоматически. Тексты источников отправляются выбранному провайдеру — учитывайте его политику конфиденциальности. Для хорошего синтеза нужны модели 14B+ или внешний API.

> **Примечание.** Список моделей Groq меняется. Актуальный список: https://console.groq.com/docs/models
> Рекомендуемые замены для текущих версий: `openai/gpt-oss-120b` (сильная модель), `qwen/qwen3.8-27b` (многоязычная).

## Режимы публикации

Задаются в «Настройки проекта → Публикация»:

- **Ручное утверждение** — каждый пост ждёт решения редактора («Черновики → На проверке»).
- **Полуавтоматически** — пост проходит автопроверки (источники, длина, заголовок, язык); без замечаний уходит в каналы сам, иначе остаётся на проверке с причиной.
- **Автопубликация** — обычные замечания не задерживают пост; на проверке остаются только пустой/слишком короткий текст, неполученная короткая статья (при единственном источнике) и несоответствие языку.

Нужен хотя бы один включённый канал. Автопроверки не заменяют проверку фактов. Расписание генерации задаётся в «Каналы и расписание».

## Каналы публикации

На странице «Каналы и расписание» можно добавить несколько каналов. Секреты (`webhook` signature, VK `access_token`, Discord webhook URL) шифруются в БД ключом из `SECRET_KEY` и в API не возвращаются.

### Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и добавьте его администратором канала с правом публикации.
2. Укажите `TELEGRAM_BOT_TOKEN` в `.env` и пересоздайте сервисы. Для production VPS:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

Для локального запуска используйте `docker compose up -d`.

3. «Каналы и расписание → Добавить канал → Telegram», введите `@имя_канала`, нажмите «Проверить доступ» (ничего не публикует).

Подписчикам уходят заголовок, текст и названия источников; номера `[1]`, `[2]` убираются. Картинка идёт тем же сообщением, а если текст длиннее лимита подписи — отдельным сообщением перед текстом. Повторная отправка того же текста в канал блокируется на 24 часа.

### ВКонтакте

1. Создайте ключ доступа сообщества с правами `wall` и `photos` (или задайте `VK_ACCESS_TOKEN` в окружении и укажите `token_env` в канале).
2. «Добавить канал → ВКонтакте», укажите `owner_id` сообщества (обычно с минусом, например `-123456789`) и токен.
3. «Проверить доступ» запрашивает `groups.getById` и ничего не публикует.

### Discord

1. В настройках текстового канала Discord: Интеграция → Вебхуки → создать вебхук, скопировать URL.
2. «Добавить канал → Discord», вставьте URL. Он хранится зашифрованным и при правке не показывается; пустое поле оставляет прежний URL.
3. Pulse отправляет embed с заголовком, текстом, картинкой и ссылками на источники.

### Webhook

POST с JSON-телом черновика. Необязательный секрет даёт заголовок `X-Pulse-Signature` (HMAC-SHA256). Заголовок `Idempotency-Key` позволяет получателю отбрасывать повторы. URL проходит SSRF-проверку.

## MinHash (дедуп)

Перед эмбеддингами worker считает MinHash-сигнатуру текста и через LSH ищет близкие уже сохранённые материалы. При сходстве ≥ `MINHASH_THRESHOLD` новый материал помечается как дубликат и не идёт в нейросетевую кластеризацию. Отключить: `MINHASH_DEDUP_ENABLED=false`.

## Пароль администратора

`ADMIN_PASSWORD` применяется только при первом запуске. Сброс:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api python -m app.admin reset-password [--email user@example.com]
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api python -m app.admin list-users
```

Для локальной установки опустите `-f docker-compose.yml -f docker-compose.prod.yml`.

## Тип канала

Тип задаётся в настройках проекта и решает, как материал попадает в публикацию.

| Тип | Как отбираются материалы |
|---|---|
| **Новостной** (по умолчанию) | Материалы об одном событии группируются в сюжеты. В публикацию идут сюжеты, в которых не меньше `min_items` источников и которые ещё в окне `window_hours`. Вес: охват, авторитетность, свежесть, скорость роста, близость к теме. |
| **Тематический (подборка)** | Каждое видео, статья или пост — самостоятельный кандидат: второй источник не нужен. Сюжетом остаются только пересказы одного материала (порог сходства не ниже 0.88). Кандидат живёт `curated_window_hours` (по умолчанию 14 дней). Вес: близость к теме 0.55, вовлечённость 0.15 (просмотры, оценки), насыщенность 0.10 (сколько текста удалось получить), авторитетность 0.10, свежесть 0.10. Веса новостного режима из настроек на подборку не действуют. |
| **Смешанный** | RSS-ленты и Telegram дают новостные сюжеты, YouTube, веб-поиск, сайты и Reddit — подборку. У каждого источника режим можно переопределить. |

В подборке время материала — момент, когда Pulse его нашёл: видео двухлетней давности, найденное сегодня, —
свежий кандидат. Исходная дата сохраняется в `meta.published_original`. Ссылки, которые проект уже видел,
повторно не добавляются (таблица `content_seen`, хранится год), даже если материал удалён по `RETENTION_DAYS`.

Формат поста выбирается по материалу: новость — один рассказ из нескольких источников, видео — пост-рекомендация
по расшифровке, статья — разбор с главными тезисами, пост — пересказ. Своя «Инструкция для модели» в настройках
проекта заменяет все форматы. В режиме генерации «Авто» подборочные посты всегда пишет модель:
экстрактивная сборка из первых фраз описания видео не годится.

Тип канала действует на материалы, собранные после сохранения настроек.

## Контент-план

Каждое расписание на странице «Каналы и расписание» — это слот плана. Помимо времени (cron), формата
(пост или дайджест) и числа сюжетов у слота есть:

- **Что публиковать** — новости, видео, статьи, посты или любой материал. Например, «видео в 10:00»,
  «статья в 14:00» и «статья в 19:00» дают план «1 видео и 2 статьи в день».
- **Когда готовить черновик** — от «в момент слота» до «за сутки». Черновик создаётся заранее, чтобы редактор
  успел его проверить, а публикация уходит ко времени слота. Пост, утверждённый после слота, уходит сразу.

В настройках проекта есть **пауза между постами из одного источника**: если YouTube-канал выложил пять видео
сразу, в канал попадёт одно, а слоты займут другие источники. За один запуск расписания берётся не больше
одного сюжета из источника.

Страница **«Контент-план»** показывает слоты на 3, 7 или 14 дней вперёд и итоги за последние сутки: черновик
и его статус, «нечего было публиковать» или ошибку генерации. Для будущих слотов видно, сколько подходящих
материалов есть прямо сейчас; если их нет, слот помечен предупреждением.

## Источники

Pulse собирает материалы только из подключённых вами источников:

| Источник | Что указать | Как работает |
|---|---|---|
| **RSS-лента** | адрес ленты или файл OPML | Короткие фрагменты дозагружаются со страницы статьи (лимит 2 МБ, защита от SSRF). |
| **Google Новости** | поисковый запрос | Запрос превращается в RSS-ленту Google News. Уточняйте широкие запросы (`"Python разработка" -змея`, `site:habr.com`). |
| **YouTube** | канал (`youtube.com/@name`, `/channel/UC…`), плейлист (`?list=…`) или поисковый запрос | Канал и плейлист читаются через RSS YouTube (последние 15 видео, просмотры и оценки), запрос — через SearXNG. Текст видео — субтитры (`youtube-transcript-api`): сначала ручные на языке проекта, затем автоматические, затем любые. Ключ API не нужен. |
| **Веб-поиск** | запрос, категория, период | Ищет статьи на любых сайтах через SearXNG; полный текст страниц дозагружается. |
| **Сайт без RSS** | страница раздела или блога | Если в `<link rel="alternate">` есть лента, читается она. Иначе берутся ссылки на статьи со страницы (тот же домен, без навигации, тегов и служебных разделов). |
| **Reddit** | сабреддит, сортировка, период | Публичная Atom-лента. Ссылочный пост ведёт на внешнюю статью или видео, текстовый пост — на себя. Анонимный JSON API Reddit закрыт, поэтому числа апвоутов нет. |
| **Telegram** | публичный канал (`@name`, `t.me/name`) | Веб-превью `t.me/s/канал`: текст, картинка и просмотры поста без бота и входа в аккаунт. |

Для новостных материалов действует окно проекта: старше `window_hours` (по умолчанию 48 ч) — устаревшие, в сюжеты не попадают.

**Ограничения площадок.** SearXNG опрашивает публичные поисковики, и при частых запросах они начинают
отвечать капчей, поэтому опрашивайте поиск раз в 6–12 часов. Reddit при частых запросах отвечает 429.
Субтитры YouTube с IP облачных провайдеров часто блокируются: задайте `YOUTUBE_PROXY_URL`. Без субтитров пост
пишется по описанию видео.

## Порог сходства

«Порог сходства» определяет, когда два материала считаются одним событием.
Подобрать его на размеченных данных:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api python scripts/eval_clustering.py --data /app/sample_data/demo_news_hard.jsonl --provider stub   # проверка скрипта
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T api python scripts/export_for_labeling.py --project 1 > to_label.csv                              # выгрузка для разметки
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T api python scripts/eval_clustering.py --data - --format csv --provider openai < to_label.csv     # оценка
```

В `to_label.csv` исправьте колонку `gold` (одинаковая метка = одно событие), затем перенесите лучший порог в настройки проекта. Для локального запуска используйте `docker compose` без production overlay.
